1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
Gastem is an institutional-grade, multi-token game item protocol built on Botchain.
By consolidating in-game currencies (Gold), stackable consumables (Potions, Scrolls),
and exclusive 1-of-1 legendary equipment (Swords, Shields, Relics) into a single,
battle-tested ERC-1155 smart contract, Gastem eliminates the friction, high gas
costs, and contract fragmentation that plague current Web3 games.


2. THE PROBLEM: FRAGMENTATION IN WEB3 GAMING
--------------------------------------------------------------------------------
* Tripled Smart Contract Overhead:
  Existing games deploy separate ERC-20 contracts for gold/currency, ERC-1155
  for materials/potions, and ERC-721 for unique weapons. This fragments player
  inventories and tripling gas/deployment costs.

* Friction in Player Experience:
  Players must approve multiple contracts (ERC-20 + ERC-721 + ERC-1155) to trade
  or interact with game loops.

* No Atomic Multi-Asset Swaps:
  Transferring an adventurer's loadout (e.g. 500 gold, 3 potions, 1 sword) requires
  multiple distinct transactions across different contracts, risking partial
  execution and failed trades.

* Off-Chain Metadata Vulnerability:
  Traditional NFT games rely on centralized IPFS gateways or HTTP links that
  experience outages, link rot, or gateway timeouts.


3. THE SOLUTION: GASTEM PROTOCOL
--------------------------------------------------------------------------------
Gastem unifies all game assets into a single ERC-1155 architecture on Botchain:

* ID 1 = Realm Gold:
  Fungible, zero-decimals currency for microtransactions, trade, and rewards.

* IDs 100 - 999 = Fungible Consumables:
  Stackable game assets (Health/Mana Potions, Elixirs, Scrolls) with optional
  hard-capped supplies (e.g. maxSupply 500) or unlimited circulation.

* IDs 1,000,000+ = Unique 1-of-1 Legendary Relics:
  Auto-incremented, strictly unique items where maxSupply is locked to 1.
  A custom override in the ERC-1155 update hook guarantees that no unique ID
  can ever be minted a second time, even if burned by a player.

* 100% On-Chain Base64 Metadata:
  Dynamic SVG art and complete OpenSea/ERC-1155 compliant JSON metadata generated
  directly by the EVM bytecode with zero off-chain dependencies.

* Atomic Batch Transactions:
  Players transfer combinations of Gold, Potions, and Legendary Swords in a
  single `safeBatchTransferFrom` transaction.

5. TECHNICAL ARCHITECTURE & INNOVATION
--------------------------------------------------------------------------------
* Solidity ^0.8.24 + OpenZeppelin Contracts v5.2.0:
  Built with modern EVM efficiency and custom errors for minimal gas overhead.

* Multiple-Inheritance Conflict Resolution:
  Cleanly overrides `_update` and `supportsInterface` across `ERC1155`,
  `ERC1155Supply`, and `AccessControl`.

* Replay-Proof Unique Minting:
  Internal tracking ensures unique items can never be re-issued, preserving
  digital scarcity under all conditions.

* Zero-Environment-Variable Sync Pipeline:
  Automated frontend scripts (`npm run sync`) synchronize ABI and contract
  deployments directly from Foundry artifacts into typed TypeScript configurations,
  eliminating human error during deployments.
